# 复述 — ESP32-S31 语音复述（INMP441 → 离线识别 → BLE + SYN6288）

对着麦克风说一句话 → ESP32 识别 → 文字经 BLE Notify 推到手机显示 → 同时让 SYN6288 念出来。

本目录是 `喇叭/` 下的独立子工程（同级还有 `../手机接收`）。
各工程共用同一套 BLE 身份：广播名 **`kskbl zdjd`**，Service `6a400001-…`，
Write `6a400002-…`，Notify `6a400003-…`（CCCD `00002902-…` 由协议栈自动生成）。
手机调试助手的配置可以直接复用，刷哪个模块就连哪个（同一时间只能跑一个）。

---

## 1. 先说要紧的：离线识别到底能做到什么

**结论：通用中文大词表 ASR 在 ESP32-S31 上跑不动；本模块用的是"自学习模板匹配"，
能认出你教过的句子，认不出没教过的任意中文。**

### 1.1 为什么通用离线 ASR 不行（逐条依据）

| 方案 | 实际情况 | 结论 |
|---|---|---|
| **esp-sr**（乐鑫 WakeNet / MultiNet） | 本机 IDF v6.1 的 147 个内置组件里**没有** esp-sr，它要靠组件管理器单独装，且官方按芯片提供预编译静态库（esp32 / s2 / s3 / c3 / c6 / p4 等）；`esp32s31` 是 preview 目标，没有对应库 | 不可用（不是配置问题，是没有二进制） |
| **whisper.cpp tiny** | 39M 参数，即使 int8 量化也要 ~40MB 模型 + 上百 MB 运行内存，且需要大量矩阵乘算力 | 差 1~2 个数量级，硬塞必然 OOM |
| **vosk small-cn** | 中文小模型 42MB，官方明确面向 PC/手机 | 同上 |
| **云端 ASR** | 用户本轮明确要求先不上云 | 留给方案 A（见 1.3） |

判据不是"我觉得跑不动"，而是：**芯片没有对应的预编译库**，或者**模型体积远大于可用 RAM**。
本工程编译产物约 1.7MB、分区 4MB，Flash 不是瓶颈；瓶颈是 RAM 和"没有 s31 的推理库"。

### 1.2 实际采用的方案：自学习 + MFCC + DTW

```
麦克风 16kHz → 每 10ms 一帧 → MFCC 13 维 → 端点检测（VAD）
   → 一句话的特征序列（最多 2s / 200 帧）
   → 与已存模板逐条做 DTW 对齐 → 距离 < 阈值 ⇒ 判定为那句话
```

- **教一句**：手机发 `EN:你好`，设备提示"请说出这句话"，你说完它存一条模板进 NVS
- **认一句**：手机发 `ASR` 打开监听，说"你好" → 命中 → Notify `ASR:你好` + 播报"你好"
- 最多 **8 条**句子，单句最长 **2.0 秒**；说话人自己教自己用，识别率最好

这是一种真实的、在 MCU 上跑了三十年的孤立词识别方法（DTW 模板匹配），
**不是假识别**：没有任何"固定回复"写死在代码里，识别结果完全来自你录入的模板；
没有模板时它明确回 `ASR:? NOTMPL`，而不是编一个答案。

### 1.3 想要"任意中文"怎么办（方案 A，未实现）

接云端 ASR：录到一句话 → HTTPS 上传 PCM（或 opus）→ 拿回文本 → Notify + SYN6288。
和 `音色/` 模块调 DeepSeek TTS 是同一套套路（Wi-Fi + HTTPS + 分块收发），
难点从"算力"变成"流量与时延"，代码量比现在少。
本模块预留了接入点：`asr.c` 的 `on_utterance_done()` 里，命中失败的分支就是挂云端的地方。

## 2. 接线

### 2.1 INMP441 麦克风（I2S）

| ESP32-S31 | 方向 | INMP441 | 说明 |
|---|---|---|---|
| **GPIO19** | → | **SCK** | 位时钟（BCLK） |
| **GPIO46** | → | **WS** | 帧时钟（LRCLK） |
| **GPIO13** | ← | **SD** | 数据（DIN） |
| **3V3** | → | **L/R** | 接 VDD = 右声道输出（代码里 `slot_mask = RIGHT`） |
| **3V3** | → | **VDD** | 供电 |
| **GND** | — | **GND** | 必须共地 |

### 2.2 SYN6288 喇叭（UART1）

| ESP32-S31 | 方向 | SYN6288 | 说明 |
|---|---|---|---|
| **GPIO09** | → | **RXD** | ESP32 的 TX 接模块 RX（交叉） |
| **GPIO08** | ← | **TXD** | ESP32 的 RX 接模块 TX（交叉） |
| **GPIO12** | ← | **BY** | 忙信号：高=正在合成播放，低=空闲 |
| **3V3** | — | **VCC** | 与 `喇叭` 模块接线一致 |
| **GND** | — | **GND** | 必须共地 |

### 2.3 引脚冲突核对

| 引脚 | 本模块用途 | 其它模块 |
|---|---|---|
| GPIO8 / 9 / 12 | SYN6288 | `喇叭` 同款，不冲突 |
| GPIO13 / 19 / 46 | INMP441 | 与 `串口`（58/59）、`音色`（I2S 15/16/17 或 PDM 17）都不冲突 |
| GPIO33 / 34 | USB PHY 占用 | **不要用** |
| GPIO29 / GPIO41 | `not bonded` | **不可用** |

依据：`soc/esp32s31/include/soc/soc_caps.h` 的 `SOC_GPIO_VALID_GPIO_MASK`
只排除 BIT29 与 BIT41；`SOC_GPIO_PIN_COUNT = 62`。

## 3. 怎么用（手机端操作顺序）

用任意 BLE 调试助手（nRF Connect / 蓝牙调试器等）连 `kskbl zdjd`，
向 **Write 特征 `6a400002-…`** 发 UTF-8 文本，订阅 **Notify `6a400003-…`** 看回执。

| 步骤 | 发什么 | 会收到 | 说明 |
|---|---|---|---|
| 1 | `PING` | `PONG` | 确认连的是这个模块 |
| 2 | `EN:你好` | `OK:ENROLLING 你好` | 设备说"请说出这句话"，接着说"你好" |
| 3 | （说完） | `OK:ENROLLED 你好` | 模板已存 NVS，掉电不丢 |
| 4 | `EN:开灯` + 说"开灯" | `OK:ENROLLED 开灯` | 再教第二句 |
| 5 | `LIST` | `LIST:2` / `T1:你好` / `T2:开灯` | 看已存模板 |
| 6 | `ASR` | `OK:ASRON 2` | 打开监听 |
| 7 | 说"你好" | `ASR:你好` + 喇叭念"你好" | 这就是验收现象 |
| 8 | `ASR:OFF` 或 `STOP` | `OK:ASROFF` | 关掉监听 |

其它命令：

| 命令 | 作用 |
|---|---|
| `DEL:1` 或 `DEL:你好` | 删第 1 条 / 删这条标签 |
| `CLEAR` | 清空全部模板 |
| `TH:15` | 调判定阈值（默认 18.0，**越小越严格**） |
| `SAY:随便一句话` | 直接播报，不经识别（调试 SYN6288 用） |
| 其它任意文本 | 兼容 `喇叭` 模块：直接播报 |

> BLE 单次写只有 20 字节（MTU 23），一条长文本会被拆成多次写。
> 驱动把连续写入拼起来，**静默 250ms 视为一条命令结束**，所以发完别马上发下一条。

## 4. 实现要点

### 4.1 I2S 采集（`mic_i2s.c`）

| 配置 | 值 | 为什么 |
|---|---|---|
| 采样率 | **16kHz** | 语音识别的经典带宽（电话语音 8kHz），比 48kHz 省一半算力与 DMA 带宽 |
| 槽位 | **32bit** | INMP441 输出 24bit 左对齐，用 32bit 槽接住后右移 16 位取高 16bit，不丢精度 |
| 声道 | `slot_mask = RIGHT` | 模块 L/R 接 VDD，数据在右槽位；选错会得到"左右交错、两倍速"的怪声 |
| 格式 | Philips（`msb_right=false`） | INMP441 手册的标准 I2S 时序 |
| DMA | 6 × 240 帧 ≈ 90ms | 抖动下不丢样本 |

### 4.2 端点检测（`asr.c`）

- 噪声底 `s_floor` 用慢速 EMA 跟踪（只在静音时更新），阈值 = `max(floor×3, 180)`
- 连续 3 帧（30ms）过阈值 → 开始记录，并**回捞 300ms 预滚**，避免吃掉字头
- 连续 25 帧（250ms）静音 → 认为说完
- 播放期间**不听**（`tts_busy()`），否则喇叭念出来的字会被自己识别回去，形成自激复读

### 4.3 特征与比对（`fft.c` / `mfcc.c` / `dtw.c`）

- 25ms 帧长 / 10ms 帧移，Hamming 窗，预加重 0.97，512 点 FFT（自己实现，旋转因子预计算）
- 26 个 Mel 三角滤波器（60–7600Hz），DCT 取 13 维，**丢弃 c0**（能量项，受说话远近影响太大）
- 每句做 **CMN**（倒谱均值归一化），消掉音量与麦克风频响的整体偏移
- DTW 带 Sakoe-Chiba 带宽约束（±(长度差 + n/8) 帧），防止两条不相关语音被"硬对齐"出小距离

### 4.4 内存占用

| 项 | 大小 |
|---|---|
| 8 条模板 | 8 × 200 × 13 × 2B ≈ **41.6KB** |
| 当前语句特征 | 200 × 13 × 2B ≈ **5.2KB** |
| 预滚环 | 30 × 13 × 2B ≈ **0.8KB** |
| 音频 PCM | **不缓存**（流式算特征，2s 的 16kHz PCM 若缓存要 64KB） |

启动日志会打印 `空闲堆 N 字节`，可据此判断余量。

## 5. 编译与烧录

**必须放到纯 ASCII 路径编译**：ESP-IDF 的 gcc 处理不了中文路径
（`-specs` 里中文会被转成换行符，报 `cannot read spec file`）。
本机做法：源码在中文目录，编译副本在 `C:\espwork\maikefeng`。

```bat
:: 第一次
cd /d C:\espwork\maikefeng
build.bat set-target esp32s31

:: 之后
build.bat
```

`build.bat` 已经内置了 IDF 环境变量与 `--preview`，**不要**在未激活的普通终端里直接敲 `idf.py`。

烧录有两种方式，**推荐用 `flash.bat`**（不重新编译，直接烧已有产物）：

```bat
cd /d C:\espwork\maikefeng
flash.bat                :: 自动找 CH343/CH340 串口并烧
flash.bat COM8           :: 指定串口
flash.bat COM8 check     :: 只读芯片 ID，不写入
```

`flash.bat` 直接调 esptool 读 `build_check\flash_args`（bootloader `0x2000` /
partition-table `0x8000` / app **`0x70000`**），不经过 ninja 与 gcc，
所以**放在中文路径下也能烧**（编译才要求纯 ASCII）。

```bat
:: 或者用 IDF 自己的命令（要求纯 ASCII 路径）
idf.py -B build_check --preview -p COM8 flash
```

### 5.1 本机编译实测（2026-11-24）

```
maikefeng.bin  0xe2ce0 = 928,992 字节（约 907KB）
app 分区 0x400000 = 4MB，剩余 0x31d320 = 78%
bootloader     0x4cc0，剩余 20%
警告 0 条（-Werror 生效，有警告就编不过）
```

两个必须知道的编译坑：

1. **`partitions.csv` 必须显式启用**。只在工程根放一个 `partitions.csv` 是不够的，
   `sdkconfig.defaults` 里必须有
   `CONFIG_PARTITION_TABLE_CUSTOM=y` + `CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="partitions.csv"`，
   否则 IDF 会用内置 single-app（**app 只有 1MB**），本工程 907KB 只剩 11%，
   模板或代码再多一点就溢出。
2. **并行度用 1**。本机 8GB 内存 + 安全软件常驻，`IDF_PY_BUILD_JOBS=2/3` 时
   多次出现 gcc 被挂起（obj 数不涨、CPU 归零）甚至多个 ninja 同时开工的僵死，
   `build.bat` 里固定为 `1`，慢但一次过。
3. **不要全局开 `-O2`**。`CONFIG_COMPILER_OPTIMIZATION_PERF` 会让 mbedtls 的
   `ssl_tls.c` 编译时吃掉 1GB 以上内存并挂死；本工程只在 `main/CMakeLists.txt`
   里对本模块源码加 `-O2`。

> 注意：`sdkconfig.defaults` 把 console 挪到了 **USB Serial/JTAG**，
> 所以 CH343 那个 COM 口上看不到日志，要看日志请插板子的原生 USB 口。

## 6. 验收

1. 上电，串口（原生 USB）看到 `离线识别就绪：模板 0/8，阈值 18.0`
2. 手机连 `kskbl zdjd`，发 `PING` → 收 `PONG`
3. 发 `EN:你好` → 喇叭说"请说出这句话" → 说"你好" → 收 `OK:ENROLLED 你好`
4. 发 `ASR` → 收 `OK:ASRON 1`
5. 说"你好" → 手机收到 `ASR:你好`，喇叭念"你好"，串口打印 `命中: 你好 (d=… <= 18.0)`
6. 说一句没教过的话 → 收 `ASR:? d=… th=18.0`，喇叭不出声

**BY 忙信号验证**：播报期间用万用表量 GPIO12，应为高电平；播完回低。

## 7. 不工作时按这个顺序查（反证自检）

| # | 检查 | 现象与判断 |
|---|---|---|
| 1 | I2S 三根线 SCK/WS/SD | 接反或漏接 → 串口正常但 `检测到说话` 永远不出现；可先用 `SAY:测试` 确认喇叭链路 |
| 2 | L/R 脚 | 接 GND 会变成左声道，代码只取右槽位 → 全是静音（数值接近 0） |
| 3 | 采样率/位宽 | 串口打印 `I2S RX 就绪 … 16000Hz 32bit槽/取右声道`，与实际接线不一致就查 `mic_i2s.h` |
| 4 | 模型真跑起来了 | 录一句看串口是否有 `语句结束: N 帧`；没有帧数说明 VAD 没触发（噪声底/阈值问题） |
| 5 | SYN6288 TX/RX 交叉 + 9600 | 串口回 `WARN:NOBY` 或 `ERR:UART` → 引脚没交叉或波特率不对 |
| 6 | 文本转 GBK | 回 `ERR:NOGB` → 文本里有 GB2312 之外的字符（emoji、生僻字） |
| 7 | BLE 是否连对设备 | 广播名必须是 `kskbl zdjd`（含空格）；`PING` 不回就是连错或没订阅 Notify |

阈值调法：认错（把 A 认成 B）就把 `TH:` 调小；该认的认不出就调大，同时看串口打印的 `d` 值。

## 8. 已知限制

- **只能认教过的句子**，最多 8 条、单句 2 秒；不是通用中文听写
- **与说话人绑定**：换个人说同一句，距离会明显变大，可能认不出
- 环境噪声大时 VAD 会误触发，可把 `ASR_MIN_FRAMES` 调大或用 `ASR:OFF` 手动控制
- 播报期间不收音，所以"边说边听"不成立（这是刻意的，防自激）
- 模板存 NVS，`CLEAR` 或擦除 flash 后需要重新教
